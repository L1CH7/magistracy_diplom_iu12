## 🎯 Достигнутые элементы

### 1. MapLibre Маркеры (маркеры на карте)

**Описание:** Реализована система отображения маркеров трёх типов: From (начало маршрута), To (конец маршрута), Via (промежуточные точки).

**Реализация:**
- `createMarkerElement(color)` - создание DOM-элементов маркеров с цветовой кодировкой
- `_addMarkerToMap(lngLat, color)` - добавление маркера на карту MapLibre
- Маркеры для From/To: белое заполнение + цветная граница (16x16px)
- Маркеры для Via: цветное заполнение + чёрная граница (12x12px)

**Цветовая схема:**
- From: #2563eb (синий)
- To: #dc2626 (красный)
- Via: пользовательские цвета из палитры (#8b5cf6, #06b6d4, #14b8a6, #f59e0b, и т.д.)

**Файлы:**
- `src/client/assets/map.html` (строки 44-71): функции создания и добавления маркеров

### 2. Управление маршрутными точками

**Описание:** Система для добавления, удаления и переупорядочения маршрутных точек через UI.

**Реализация:**
- `_add_point(point_type, lon, lat)` - добавление точки (from/to/via)
- `_remove_point(idx)` - удаление точки по индексу
- `_move_point(from_idx, direction)` - переупорядочение точек (вверх/вниз)
- Хранение точек в массиве: первая = From, последняя = To, остальные = Via

**Selected Points Panel:**
- Отображение текущего списка маршрутных точек
- Визуализация с цветовой кодировкой
- Кнопки удаления для каждой точки
- Поддержка drag-and-drop для переупорядочения (планируется R-D-2)

**Файлы:**
- `src/client/gui.py` (строки 680-770): функции управления точками
- `src/client/gui.py` (строки 342-359): Selected Points panel в боковой панели

### 3. Zoom Slider - Двусторонняя синхронизация

**Описание:** Синхронизация зум-слайдера (UI) с картой без использования polling, через HTTP API.

**Архитектура:**
- **Python сторона:** `ZoomAPIHandler` на порту 9999 обслуживает `/api/zoom?value=X`
- **JavaScript сторона:** MapLibre генерирует события зума и отправляет HTTP запросы
- **Обновление UI:** `_handle_zoom_from_js()` получает значение зума и обновляет слайдер
- **Вызов из UI:** Перемещение слайдера вызывает `map.setZoom(value)` через JavaScript

**Преимущества:**
- Нет polling (экономия ресурсов)
- Реактивное обновление (пользователь видит изменения мгновенно)
- Работает в обе стороны: карта→UI и UI→карта

**Файлы:**
- `src/client/gui.py` (строки 73-107): `ZoomAPIHandler` класс
- `src/client/gui.py` (строки 507-530): `_handle_zoom_from_js()` обработчик
- `src/client/assets/map.html` (строки 246-269): обработка zoom событий и HTTP запросы

### 4. Контекстное меню для выбора точек

**Описание:** Правый клик на карте открывает меню для выбора типа маршрутной точки.

**Функциональность:**
- Правый клик на карте → фиксируется координата
- Появляется меню с опциями: "Отсюда" (From), "Сюда" (To), "Добавить точку" (Via)
- Выбор опции добавляет точку на карту
- Новые маркеры сразу отображаются с правильной позицией

**HTTP API для коммуникации:**
- JavaScript отправляет позицию контекстного меню на Python
- Python-сторона обновляет UI, вызывает диалог, вносит точку в карту

**Файлы:**
- `src/client/assets/map.html` (строки 269-289): обработчик контекстного меню
- `src/client/gui.py` (строки 595-650): `_on_context_menu_pos_received()` и `_show_map_context_menu()`

### 5. Асинхронная инициализация MapLibre (mapLoaded флаг + pendingOperations очередь)

**Описание:** Решение проблемы асинхронной инициализации MapLibre - операции, добавленные до загрузки карты, теперь правильно выполняются после.

**Архитектура:**
- `mapLoaded` флаг отслеживает момент, когда `map.on('load')` событие произойдёт
- `pendingOperations` массив собирает операции (setStart, setEnd, addMarker) до готовности карты
- Когда карта загружена, все операции из очереди выполняются в правильном порядке

**Преимущества:**
- Надёжность: операции всегда выполняются в правильном состоянии карты
- Отсутствие race conditions
- Упрощённый код - не нужны сложные синхронизационные механизмы

**Файлы:**
- `src/client/assets/map.html` (строки 35-37): флаг и очередь
- `src/client/assets/map.html` (строки 73-95): функции setStart/setEnd/addMarker с проверкой mapLoaded
- `src/client/assets/map.html` (строки 221-240): обработка pendingOperations в map.on('load')

## 🏗️ Архитектурные улучшения

### Исправлена утечка памяти

**Проблема:** Переменные `startPt`, `endPt`, `viaPts`, `allMarkers` были перереобъявлены внутри `map.on('load')` колбэка, создавая дополнительные локальные переменные вместо использования глобальных.

**Решение:** Удалены перереобъявления - теперь используются только глобальные переменные, что избегает утечек памяти и упрощает отладку.

### Правильная организация JavaScript кода

**Улучшения:**
- Глобальная инициализация переменных в начале файла
- Вспомогательные функции (createMarkerElement, _addMarkerToMap) отделены от основной логики
- Все event listeners подписываются только внутри `map.on('load')` - гарантирует что карта готова
- Четкое разделение: инициализация → загрузка → события
