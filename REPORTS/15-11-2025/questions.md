4. Когда миграция на C++:
   - SimulationCore (агенты + физика): Python → C++ = ? speedup?
   - RoutingCoordinator: остаётся в PostgreSQL (pgRouting).
   - Интеграция: C++ через pybind11 или gRPC?

   - Prometheus metrics: simulation_step_duration_ms, routing_duration_ms, db_update_duration_ms.

### 8. **Тестирование: Baseline vs MAS**

**Контекст:** Для диссертации нужно показать, что МАС координация даёт выигрыш.

**Вопросы:**

```
1. Baseline (без МАС):
   - Каждый агент строит кратчайший маршрут (pgr_dijkstra).
   - Координатор НЕ распределяет (agents выбирают сами).
   - Метрики: avg_travel_time, max_congestion, throughput.

2. MAS (с координацией):
   - Координатор получает K маршрутов для каждого агента.
   - Распределяет так, чтобы min(max_congestion) или min(total_time).
   - Метрики: те же.

3. Сценарии тестов:
   - Сценарий 1: 100 агентов, все OD пары через один узел (bottleneck).
   - Сценарий 2: 1000 агентов, random OD пары (Москва МКАД).
   - Сценарий 3: 500 агентов + 10 priority=20 (скорая).

4. Ожидаемый результат:
   - MAS: avg_travel_time на 10-30% меньше чем Baseline?
   - MAS: max_congestion на 20-50% меньше?
   - Если нет выигрыша — МАС бесполезен (не защитите диссертацию).

5. Как измерить throughput:
```

throughput = кол-во агентов, достигших цели / время симуляции

```
MAS должен увеличить throughput (меньше заторов → быстрее едут).

6. Визуализация результатов:
- Графики: Baseline vs MAS (travel_time, congestion, throughput).
- Heatmap загруженности (до/после МАС).
- Нужно для отчёта и защиты.
```

**Почему критично:** Если нет метрик и сравнения → нет научной новизны. Это основа диссертации.
