# ЗАКЛЮЧЕНИЕ

В результате выполнения научно-исследовательской работы решена задача разработки мультиагентной навигационной системы на основе данных OpenStreetMap с использованием PostgreSQL/PostGIS/pgRouting для построения графа дорожной сети и поиска альтернативных маршрутов с учётом динамической загрузки участков дорог. Особенностью решения является интеграция алгоритма pgr_KSP для поиска k кратчайших путей, модели пропускной способности на основе безопасной дистанции и функции задержки BPR для моделирования влияния загрузки на время прохождения участков. Микросервисная архитектура обеспечила разделение ответственности между компонентами системы (загрузка OSM, построение графа, маршрутизация, управление трафиком, симуляция агентов), что упрощает масштабирование и сопровождение.

В рамках работы исследована структура данных OpenStreetMap и формат Mapbox Vector Tiles для эффективной передачи векторной геометрии дорог, спроектирована многослойная база данных PostgreSQL/PostGIS с схемами osm (сырые данные) и graphs (топологический граф) и триггерами для автоматического вычисления характеристик рёбер, реализован алгоритм построения графа из данных OSM с обнаружением пересечений путей и сегментацией на рёбра, интегрирована модель пропускной способности и функция задержки BPR в генерируемых полях PostgreSQL, разработана микросервисная архитектура из 8 основных сервисов (data-processor, router, traffic-manager, coordinator, simulation, server, postgis, redis) и 3 observability сервисов (loki, promtail, grafana), реализован графический клиент на PyQt5 с интеграцией MapLibre GL JS для векторного рендеринга карт, организована контейнерная инфраструктура Docker Compose с 11 сервисами и настроенными healthchecks, интегрирована система логирования Loguru с агрегацией в Grafana Loki и разработкой LogQL запросов для анализа, разработана система конфигурации на основе YAML с поддержкой директивы !include и hot reload, проведено экспериментальное исследование производительности на реальных данных OpenStreetMap для г. Москвы.

Экспериментальное исследование на данных региона moscow_center (44 821 дорожных путей OSM, 59 099 узлов графа, 72 309 рёбер графа) подтвердило производительность системы: время построения графа составило ~30 секунд (требование <120 сек, запас 4.0×), время маршрутизации pgr_KSP для k=3 альтернативных маршрутов — 241.0 мс (требование <1000 мс, запас 4.1×), время генерации MVT векторного тайла на масштабе z=14 — 15.2 мс (требование <100 мс, запас 6.6×). Связность графа составила 99.96% узлов в основной компоненте (3 малые изолированные компоненты соответствуют парковкам без выездов). Потребление памяти в idle режиме составило 0.26 ГБ (256 МБ), под нагрузкой — ~1.0 ГБ, что существенно ниже требований <2 ГБ и <4 ГБ. MVT генерация оказалась в 4.4 раза быстрее предварительной оценки благодаря эффективности PostGIS `ST_AsMVT`. Распределение дорог по категориям highway показало преобладание service дорог (73.0%, подъезды/парковки), что отражает детальную OSM-разметку центра Москвы. Выявлены ограничения системы: ограничения поворотов из OSM не применяются в pgr_KSP (требуется миграция на pgr_trsp или penalty-based подход), модель capacity не учитывает светофоры и ДТП (требуется интеграция данных о светофорах и внешних источников трафика), отсутствует механизм инкрементального обновления графа (требуется двойная буферизация или инкрементальное обновление затронутых участков).

Разработанная система демонстрирует готовность к использованию для навигации в пределах московского региона и масштабирования до крупных городов. Интеграция современных технологий (PostgreSQL/PostGIS/pgRouting, Docker Compose, Loguru/Grafana Loki, MapLibre GL JS) обеспечила воспроизводимость окружения, эффективную диагностику проблем и высокое качество визуализации. Выявленные ограничения не являются критичными для исследовательского прототипа и могут быть устранены в рамках дальнейшего развития. Направления дальнейшей работы включают: интеграцию алгоритма pgr_trsp для учёта ограничений поворотов, оптимизацию построения графа для крупных регионов через пространственное разбиение, интеграцию внешних данных о трафике (TomTom, Яндекс.Пробки API), масштабирование до 1000+ одновременных агентов через горизонтальное масштабирование router service и кэширование маршрутов в Redis, реализацию инкрементального обновления графа, разработку административного клиента для мониторинга состояния системы, оптимизацию генерации MVT тайлов через предварительную генерацию и кэширование, интеграцию ML модели прогнозирования трафика на основе исторических данных загрузки рёбер.
