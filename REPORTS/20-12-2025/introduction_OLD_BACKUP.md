# ВВЕДЕНИЕ

## Актуальность темы исследования

Развитие городской транспортной инфраструктуры и рост интенсивности транспортных потоков создают необходимость в эффективных системах навигации и управления транспортом. Современные мегаполисы сталкиваются с проблемой перегрузки дорожной сети, что приводит к образованию пробок, увеличению времени в пути и повышению расхода топлива. Традиционные навигационные системы, использующие статические графы дорожной сети, не учитывают динамически изменяющуюся загрузку участков дорог, что снижает качество предлагаемых маршрутов в условиях высокой транспортной активности.

Задача построения оптимального маршрута осложняется необходимостью учёта множества факторов: текущей загрузки дорожной сети, временных ограничений движения, дорожных работ, ограничений поворотов на перекрёстках, пропускной способности участков дорог. Классические алгоритмы поиска кратчайшего пути (алгоритм Дейкстры, A*) не предоставляют пользователю альтернативных вариантов маршрута, что ограничивает возможности выбора при наличии пробок или других непредвиденных обстоятельств.

Мультиагентный подход к навигации, при котором каждый участник движения представлен автономным агентом, принимающим решения о выборе маршрута на основе текущего состояния дорожной сети, позволяет распределить транспортные потоки более равномерно. В таких системах агенты могут выбирать альтернативные маршруты при обнаружении загрузки на предпочтительном пути, что приводит к самоорганизации транспортной системы и снижению общего времени в пути для всех участников.

Для реализации мультиагентной навигационной системы требуется эффективная модель хранения и обработки геопространственных данных дорожной сети. Данные OpenStreetMap (OSM) предоставляют детальную информацию о дорогах, включая их геометрию, категорию (motorway, primary, residential), количество полос, ограничения скорости, ограничения поворотов и другие атрибуты. Однако использование OSM данных для маршрутизации требует их преобразования в топологический граф дорожной сети с учётом пересечений путей, односторонних участков, барьеров и других особенностей.

Векторные тайлы формата Mapbox Vector Tiles (MVT) обеспечивают эффективную передачу геометрических данных дорог от сервера к клиенту для интерактивного рендеринга карты. В отличие от растровых тайлов, векторные тайлы передают сырую геометрию объектов, что позволяет клиенту выполнять стилизацию, масштабирование и вращение карты без потери качества. Система прогрессивной детализации (Level of Detail, LOD) снижает объём передаваемых данных на низких масштабах за счёт фильтрации второстепенных дорог.

Моделирование загрузки дорожной сети требует оценки пропускной способности участков и влияния текущей загрузки на скорость движения. Классическая функция задержки Bureau of Public Roads (BPR) широко применяется в транспортном моделировании для описания зависимости времени прохождения участка от соотношения текущей загрузки к максимальной пропускной способности. Интеграция модели BPR в генерируемые поля PostgreSQL позволяет автоматически пересчитывать стоимость рёбер графа при изменении загрузки, обеспечивая динамическую адаптацию маршрутов.

Современные инструменты пространственных баз данных, такие как PostGIS и pgRouting, предоставляют высокопроизводительные реализации пространственных операций и алгоритмов графового анализа. Функция `pgr_KSP` (k-shortest paths) вычисляет несколько альтернативных маршрутов между двумя точками, что позволяет агентам мультиагентной системы выбирать маршруты с учётом предпочтений по длине, времени прохождения или минимизации загрузки.

Контейнеризация приложений с использованием Docker обеспечивает воспроизводимость окружения и упрощает развёртывание системы. Микросервисная архитектура разделяет функциональность на независимые сервисы (загрузка данных OSM, маршрутизация, управление трафиком, симуляция агентов), взаимодействующие через HTTP API, что повышает масштабируемость и упрощает сопровождение системы.

Система логирования на основе библиотеки Loguru с агрегацией логов в Grafana Loki позволяет оперативно диагностировать проблемы производительности и отслеживать аномалии в работе системы. Структурированное логирование с контекстом агентов (agent_id, task_id) обеспечивает трассировку выполнения запросов в распределённой системе.

Таким образом, актуальность данного исследования обусловлена необходимостью разработки эффективной мультиагентной навигационной системы, интегрирующей современные технологии пространственных баз данных, векторного рендеринга карт, контейнеризации и структурированного логирования для обеспечения высокой производительности и масштабируемости.

## Цель и задачи исследования

**Цель работы**: разработка мультиагентной навигационной системы на основе данных OpenStreetMap с использованием PostgreSQL/PostGIS/pgRouting для построения графа дорожной сети и поиска k альтернативных маршрутов с учётом динамической загрузки участков дорог.

**Задачи исследования**:

1. **Исследование структуры данных OpenStreetMap**. Изучение формата представления дорожной сети в OSM (ways, nodes, relations), классификации дорог по категориям highway, способов кодирования атрибутов (теги maxspeed, lanes, oneway, access), представления ограничений поворотов через relations типа restriction.

2. **Анализ формата Mapbox Vector Tiles (MVT)**. Исследование спецификации MVT для передачи векторной геометрии дорог, изучение функции PostGIS `ST_AsMVT` для генерации тайлов, разработка системы LOD (Level of Detail) для прогрессивной детализации карты на различных масштабах.

3. **Проектирование многослойной базы данных**. Разработка схемы `osm` для хранения сырых данных OpenStreetMap, схемы `graphs` для хранения топологического графа дорожной сети с атрибутами рёбер (length_m, capacity, current_load, cost, reverse_cost), проектирование триггеров для автоматического вычисления характеристик рёбер.

4. **Реализация алгоритма построения графа из данных OSM**. Разработка алгоритма обнаружения пересечений дорожных путей с использованием пространственных операций PostGIS, сегментация путей на рёбра графа в точках пересечений, создание узлов графа с привязкой к исходным узлам OSM.

5. **Интеграция модели пропускной способности и функции BPR**. Разработка формулы расчёта пропускной способности участка дороги на основе длины, количества полос и безопасной дистанции, реализация функции задержки BPR в генерируемых полях PostgreSQL для автоматического пересчёта стоимости рёбер при изменении загрузки.

6. **Реализация микросервисной архитектуры**. Разработка сервисов: data-processor (загрузка OSM, генерация MVT тайлов), router (построение графа, маршрутизация через pgr_KSP), traffic-manager (мониторинг загрузки, кэш в Redis), coordinator (оркестрация запросов, WebSocket), simulation (физика движения агентов).

7. **Разработка графического клиента**. Реализация GUI на PyQt5 с интеграцией MapLibre GL JS для аппаратно-ускоренного рендеринга векторных карт, обработка кликов на карте для выбора точек маршрута, отображение альтернативных маршрутов с возможностью интерактивного выбора.

8. **Организация инфраструктуры Docker Compose**. Конфигурация 11 сервисов (postgis, redis, router, data-processor, traffic-manager, coordinator, simulation, server, loki, promtail, grafana), настройка healthchecks для обеспечения корректной последовательности запуска, монтирование томов для персистентности данных.

9. **Интеграция системы логирования Loguru и Grafana Loki**. Настройка структурированного логирования в JSON Lines формат, конфигурация Promtail для доставки логов в Loki, разработка LogQL запросов для анализа ошибок и производительности, создание дашбордов Grafana.

10. **Экспериментальное исследование производительности**. Проведение измерений времени построения графа для регионов различной площади (moscow_center, moscow_mkad), измерение времени выполнения запросов маршрутизации pgr_KSP с различными значениями k, анализ времени генерации MVT тайлов на различных масштабах, оценка потребления ресурсов Docker контейнерами.

## Структура отчёта

Отчёт о научно-исследовательской работе состоит из 6 основных разделов, введения и заключения.

**Раздел 1 "Постановка задачи и анализ требований"** содержит обоснование актуальности разработки мультиагентной навигационной системы, анализ ограничений существующих подходов к маршрутизации, формулировку целей и задач исследования. Приведены функциональные и нефункциональные требования к системе, требования к производительности построения графа и маршрутизации.

**Раздел 2 "Исследование структуры данных OpenStreetMap и формата MVT"** посвящён детальному изучению способов представления дорожной сети в OpenStreetMap. Описана структура объектов OSM (ways, nodes, relations), классификация дорог по категориям highway, кодирование атрибутов в тегах. Исследован формат Mapbox Vector Tiles для передачи векторной геометрии, функция PostGIS `ST_AsMVT`, система прогрессивной детализации LOD.

**Раздел 3 "Проектирование хранилища и построение графа дорожной сети"** описывает архитектуру многослойной базы данных PostgreSQL/PostGIS. Приведены структуры таблиц схем `osm` (сырые данные) и `graphs` (топологический граф), алгоритмы обнаружения пересечений путей и сегментации на рёбра графа. Представлена математическая модель пропускной способности и функции задержки BPR, реализация вычисления стоимости рёбер через генерируемые поля PostgreSQL.

**Раздел 4 "Реализация программных модулей системы"** содержит описание микросервисной архитектуры системы. Детально рассмотрены сервисы data-processor (загрузка OSM через Overpass API, генерация MVT тайлов функцией `ST_AsMVT`), router (построение графа, маршрутизация pgr_KSP), traffic-manager (обновление загрузки рёбер, кэш в Redis), coordinator (оркестрация, WebSocket). Приведена реализация GUI клиента на PyQt5 с интеграцией MapLibre GL JS для векторного рендеринга карт.

**Раздел 5 "Инфраструктура разработки и эксплуатации системы"** посвящён организации контейнерной инфраструктуры Docker Compose. Описаны конфигурации всех 11 сервисов, healthchecks, тома для персистентности данных, сетевая конфигурация. Представлена система логирования Loguru с агрегацией в Grafana Loki, конфигурация Promtail для доставки логов, примеры LogQL запросов для анализа. Описана система конфигурации на основе YAML с поддержкой директивы `!include`, Git workflow с feature branch моделью.

**Раздел 6 "Экспериментальное исследование и оценка результатов"** содержит результаты тестирования системы на реальных данных OpenStreetMap для г. Москвы. Приведены характеристики тестовых регионов (moscow_center, moscow_mkad), статистика загруженных данных OSM. Представлены измерения производительности построения графа (33.2 секунды для moscow_center), маршрутизации pgr_KSP (127.5 мс для k=3), генерации MVT тайлов (67.3 мс для zoom=14). Проведён анализ связности графа, выявлены и описаны проблемы (фрагментация графа при малом толерансе ST_DWithin, неприменение ограничений поворотов в pgr_KSP). Выполнена оценка потребления ресурсов Docker контейнерами.

**Заключение** обобщает достигнутые результаты исследования, оценивает соответствие реализованной системы заявленным требованиям производительности, формулирует выявленные ограничения и намечает направления дальнейшего развития системы.

Отчёт содержит 29 таблиц с экспериментальными данными, 4 диаграммы Mermaid, иллюстрирующие архитектуру системы, конвейеры обработки данных и схемы баз данных. Общий объём отчёта составляет более 200 000 символов, что соответствует требованиям научно-исследовательской работы в области разработки программных систем.
