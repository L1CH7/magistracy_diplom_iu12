# Эксперименты и методика

Цель: показать, что координированное распределение агентов по альтернативным маршрутам (с учётом загрузки) превосходит наивное движение «каждый по кратчайшему» по суммарным метрикам.

## Метрики (KPI)
- Среднее время в пути (avg_travel_time), перцентили P50/P90.
- Максимальная загрузка ребра (max_edge_load) и средняя загрузка.
- Пропускная способность (throughput) — сколько агентов завершили за окно времени.
- Количество пере-роутингов на агента (stability proxy).

## Сценарии
- S1: Один узкое место (бутылочное горлышко), стартовые точки равномерно распределены.
- S2: Закрытие нескольких рёбер на критическом направлении (инцидент).
- S3: Динамическая перегрузка (эмуляция трафика), волнообразные задержки.

## Методы сравнения
- Baseline: каждый агент выбирает кратчайший путь по текущим статичным весам.
- Coordinated: координатор распределяет по K альтернативам, учитывая live-скорости и закрытия, с порогами/гистерезисом для пере-роутинга.

## Методология
- Для синтетики: SUMO генерирует фоновые потоки (randomTrips/duarouter). Наши агенты накладываются поверх и управляются координатором.
- Для метрик: сбор телеметрии в Redis Streams, агрегация в файлы `.agent_dir/out/experiments/*.json`.
- Визуализация: heatmap загрузки, графики ETA по времени, сравнение boxplot для методов.

## Примечания
- В натурных испытаниях SUMO отключаем; используем только реальную телеметрию.
- Метрики и конфигурации эксперимента сохраняем вместе для воспроизводимости.
