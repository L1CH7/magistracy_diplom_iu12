# Мультиагентная система: концепт архитектуры

Дата: 2025-10-18

## Цели
- Плавная, GPU-ускоренная клиентская карта (MapLibre GL JS в PyQt QWebEngineView).
- Масштабируемая координация 1000+ агентов: сервер — источник карт/БД/маршрутизации и координации.
- Разделение клиентов: с GUI и headless.

## Высокоуровневая архитектура
- Клиент (GUI): PyQt + QWebEngineView, внутри — MapLibre GL JS. Канал обновлений позиций — WebSocket (JS → сервер и сервер → JS), плавная анимация через requestAnimationFrame.
- Клиент (headless): Python/asyncio агент без UI, общается по WS/HTTP.
- Сервер (FastAPI):
  - REST (инициализация, маршруты, загрузка OSM),
  - WebSocket (потоки позиций/событий),
  - Координационный модуль (распределённые алгоритмы маршрутизации/разведения агентов),
  - БД: PostGIS (граф дорог, кэш слоёв, состояния), Redis (кэш/пабсаб),
  - Маршрутизация: начально NetworkX, затем pgRouting/Valhalla.
- Тайлсервер (позже): векторные/растровые тайлы (MVT/MBTiles), быстрый рендер графа/слоёв.

## Потоки данных
- GUI ←WS— Сервер: позиции агентов, слои/события; → плавная отрисовка в JS.
- Headless ↔ Сервер: периодические запросы маршрутизации/координации, обновления состояния.
- Сервер ↔ PostGIS: хранение графа/слоёв, расчёт маршрутов (pgRouting), индексы GiST/BRIN.

## Координация агентов
- Локальные правила + глобальная координация:
  - Агент локально адаптирует скорость/маршрут по локальным плотностям.
  - Сервер периодически пересчитывает рекомендации (стоимость рёбер по загруженности).
- Механизмы:
  - Стоимость рёбер = f(трафик, пробки, инциденты) — обновляется в реальном времени.
  - Алгоритмы распределённых маршрутов: многокритериальный A* / k-shortest, LWR/CTM для потоков.
  - Анти-конфликт: penalization на популярные рёбра, стахастическая диверсификация путей.

## Масштабирование
- Сервер: горизонтально (WS sticky), отдельные сервисы: маршрутизация, симуляция, кафка/редис шина.
- БД: PostGIS с репликацией/шардингом; тайлсервер со статическими стилями.
- Клиент: WS-компрессия, батчирование позиций, дельта-обновления.

## Безопасность/устойчивость
- Ограничение частоты обновлений, валидация входных данных, backpressure для WS.
- Логи/метрики (Prometheus/Grafana), трассировка запросов.
