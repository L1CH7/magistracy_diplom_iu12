# Технический отчет: Модуль маршрутизации

## Аннотация

Данный отчет описывает проектирование, реализацию и тестирование модуля маршрутизации для дорожного графа Московской агломерации. Система построена на базе PostgreSQL + pgRouting и обеспечивает динамическое изменение весов ребер графа без перестройки. Ключевые достижения: решение проблемы Out Of Memory (снижение потребления RAM с 12 ГБ до 370 МБ), стабильность поиска маршрутов (100% success rate для K=1), масштабируемость под параллельной нагрузкой (16 воркеров без деградации).

**Ключевые компромиссы:** Латентность 6.2 сек (median) против 10 мс у OSRM — осознанный обмен скорости на гибкость.

### [Глава 3: Алгоритмы маршрутизации (Runtime)](./03_routing_algorithms.md)

**Содержание:**
- Эволюция алгоритмов: провалы A* и KSP.
- Итоговое решение: Iterative Penalty Dijkstra.
- Оптимизация: Dynamic Bounding Box (BBOX × 0.3).
- Качество маршрутов: Smart Snapping (KNN на узлах), Zig-Zag Fix.
- Архитектурное разделение: `find_route` vs `find_k_routes` (SRP, YAGNI).

**Ключевые метрики:**
- BBOX ускорение: 5.9x (12.3 сек → 2.1 сек).
- Tortuosity (median): 1.36 (приемлемая извилистость).
- Разделение функций: оптимизация "горячего пути" для МАС.

**Содержание:**
- Формат данных: GeoJSON → WKB (↓ 74% размер, ↓ 83% парсинг).
- Оптимизация запросов: отложенный JOIN (↓ 50% время).

- Асинхронность: asyncpg (7x ускорение при параллельной нагрузке).

**Ключевые метрики:**
- WKB vs GeoJSON: 12 КБ vs 47 КБ.
- GiST индекс: 8200 мс → 12 мс (BBOX поиск).
- asyncpg: 62 сек → 8.7 сек (10 параллельных запросов).

## Приложения

### Приложение A: Формулы и алгоритмы

**Dynamic Bounding Box:**

$$
BBOX = Envelope(Start, End) + Buffer
$$

$$
Buffer = \max(0.015°, Distance(Start, End) \times 0.3)
$$

**Tortuosity (Извилистость):**

$$
T = \frac{L_{route}}{L_{euclid}}
$$

**Регрессионная модель:**

$$
T = k \cdot C + b, \quad C = N \times K
$$

### Приложение B: SQL-запросы

**Создание GiST индекса:**

```sql
CREATE INDEX idx_edges_geom ON graphs.edges USING GIST(geometry);
CREATE INDEX idx_nodes_geom ON graphs.nodes USING GIST(geom);
```

**Анализ связности:**

```sql
SELECT component, COUNT(*) as edge_count
FROM pgr_connectedComponents(
    'SELECT id, source_id as source, target_id as target, cost, reverse_cost FROM graphs.edges'
)
GROUP BY component
ORDER BY edge_count DESC;
```
