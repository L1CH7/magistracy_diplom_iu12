# Технический отчет: Клиентское приложение (Qt Client)

## Аннотация

Данный отчет описывает проектирование, реализацию и архитектуру клиентского приложения навигационной мультиагентной системы. Система построена на гибридной архитектуре PyQt5 + MapLibre GL JS и обеспечивает визуализацию векторных карт с аппаратным ускорением, интерактивное планирование маршрутов и интеграцию с микросервисной инфраструктурой через Gateway. Ключевые достижения: отказоустойчивая архитектура взаимодействия JavaScript-Python через QWebChannel, асинхронная обработка запросов через QThread, реактивное обновление векторных тайлов через WebSocket.

**Ключевые компромиссы:** Использование встроенного браузера (QtWebEngine) вместо нативного рендеринга — обмен производительности на гибкость и возможность использования современных веб-технологий картографии.

## Структура отчета

### [Глава 1: Архитектурный обзор](./01_architecture_overview.md)

**Содержание:**
- Гибридная архитектура: PyQt5 + MapLibre GL JS.
- Разделение ответственности: UI-слой (Qt), картографический движок (JavaScript), бизнес-логика (Python).
- Интеграция с микросервисной инфраструктурой (Gateway, Router, Data Processor).
- Мост JavaScript-Python через QWebChannel.

**Ключевые решения:**
- Выбор QtWebEngine для рендеринга карт.
- Асинхронная архитектура: QThread для блокирующих операций.
- Конфигурация через YAML с инъекцией в JavaScript.

---

### [Глава 2: Картографический движок](./02_map_engine.md)

**Содержание:**
- MapLibre GL JS: векторный рендеринг с GPU-ускорением.
- Архитектура JavaScript-модулей (ES6 modules).
- Управление состоянием карты: `map-api.js`, `points-manager.js`, `agent-animator.js`.
- Стилизация: динамическая генерация MapLibre Style Spec.
- Интеграция растровых и векторных тайлов (MVT).

**Ключевые метрики:**
- Поддержка векторных тайлов формата MVT (Mapbox Vector Tiles).
- Динамическое обновление слоев без перезагрузки карты.
- Отладочная сетка для визуализации границ тайлов.

---

### [Глава 3: Интеграция с бэкендом](./03_backend_integration.md)

**Содержание:**
- Архитектура API-клиента: `api/client.py`, `api/api_workers.py`.
- Асинхронные воркеры: `GraphFetchWorker`, `RouteFetchWorker`, `DataSocketWorker`.
- WebSocket-клиент для реактивных обновлений (`ws_client.py`).
- Обработка ошибок и таймаутов (600 сек для загрузки графа).
- Интеграция с Gateway: единая точка входа для всех запросов.

**Ключевые решения:**
- Использование `requests` (синхронный) в QThread вместо `asyncio` для упрощения.
- WebSocket для уведомлений о загрузке тайлов (`tile_downloaded`).
- Конфигурация таймаутов через YAML (`client/data.yaml`).

---

### [Глава 4: Пользовательский интерфейс](./04_user_interface.md)

**Содержание:**
- Архитектура UI: полноэкранная карта + оверлейная боковая панель.
- Компоненты: `ZoomControl`, `PointsPanel`, `RoutesPanel`, `AgentPanel`.
- Интернационализация: Qt Linguist (`.ts` → `.qm`).
- Обработка событий: сигналы/слоты Qt, JavaScript callbacks.
- Горячие клавиши: Ctrl+1/2/3 для установки точек маршрута.

**Ключевые решения:**
- Разделение `main_window.py` и `main_window_handlers.py` (SRP).
- Изоляция от системной темы (`QT_STYLE_OVERRIDE=Fusion`).
- Кастомная палитра для консистентного отображения.

---

### [Глава 5: Мост JavaScript-Python](./05_js_python_bridge.md)

**Содержание:**
- QWebChannel: двунаправленная коммуникация JavaScript ↔ Python.
- Бриджи: `config_bridge.py`, `logger_bridge.py`, `points_bridge.py`, `zoom_bridge.py`.
- Проблемы синхронизации: race conditions при обновлении зума.
- Решение: флаг `_skipNextZoomUpdate` для предотвращения циклических обновлений.
- Инъекция конфигурации: передача `apiBaseUrl` из Python в JavaScript.

**Ключевые проблемы и решения:**
- **Проблема:** Циклические обновления зума (JS → Python → JS → ...).
- **Решение:** Флаг-семафор для пропуска обновлений, инициированных Python.
- **Проблема:** Асинхронная инициализация QWebChannel.
- **Решение:** Polling через `setInterval` до готовности канала.

---

### [Глава 6: Конфигурация и сборка](./06_configuration_build.md)

**Содержание:**
- Система конфигурации: YAML + Pydantic Settings.
- Загрузчик конфигурации: `services/common/config/config_loader.py`.
- Makefile: автоматизация сборки, компиляция переводов.
- Зависимости: `requirements.txt` (PyQt5, websockets, httpx).
- Виртуальное окружение: изоляция Python 3.13.

**Ключевые файлы:**
- `configs/client/map.yaml` — конфигурация карты (LOD, стили).
- `configs/client/network.yaml` — URL Gateway.
- `configs/client/data.yaml` — таймауты API.

---

### [Глава 7: Выводы и планы развития](./07_conclusions.md)

**Содержание:**
- Технический долг (нативный рендеринг, оптимизация QWebChannel).
- Интеграция с МАС (симуляция агентов, визуализация траекторий).
- Расширение функциональности (редактирование графа, экспорт маршрутов).
- Границы применимости (десктоп vs веб-клиент).
- Честная самооценка (достижения и недостатки).

**Главный вывод:**
Гибридная архитектура обеспечила быструю разработку и гибкость, но ценой производительности. QtWebEngine добавляет 200+ МБ накладных расходов памяти. Архитектура готова к интеграции с МАС, но требует оптимизации для production-сценариев.
